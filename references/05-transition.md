# ⑤ 转场方案 — 三选一，写进 storyboard.md

根据**画风**和**歌的节奏**从下面三种里推荐一种，说理由。然后为每两个相邻镜头写明衔接方式。

## 三种方案

### 方案 1：一镜到底

整片由一台虚拟摄像机连续拍摄：推拉、上摇至天空、穿过门窗切换场景。

- **怎么实现**：一个超长 composition，`#camera` 容器用 GSAP 连续 tween `translate/scale`，场景元素分布在 `x: 0 ~ N*1920` 的一条带上，镜头横向或纵向移动把不同段落带进画面。门窗作为「遮罩口」：角色穿过去时，门框外的区域换成下一段的世界。
- **优点**：最不像「做的视频」，连贯性最强。
- **代价**：代码量最大；一个场景出错全片要重来；3 分钟以上的歌会非常难排。

### 方案 2：卡点切换

在节拍点切镜头，用**甩镜**（快速横移 + 运动模糊感）或**前景物体扫过画面**衔接。

- **怎么实现**：每镜独立 composition，切点落在 `beat_anchor`。甩镜 = 上一镜尾 0.15s 内把内容横向平移 -1200px 且淡出，下一镜头 0.15s 从 +1200px 平移进来。前景扫过 = 加一层比画面大的深色形状，0.2s 横穿全屏，穿过时切镜。
- **优点**：节奏感强，最适合副歌；实现标准化，好批量。
- **代价**：甩镜用多了会晕，主歌段要克制。

### 方案 3：拼贴快切

每 0.5~1 秒切一张画面，新画面以**卡片形式滑入**、**刷开**（wipe）进入。

- **怎么实现**：镜头比歌词更碎 —— 一句歌词里放 2~3 个画面，都是同一动作的不同瞬间（像翻绘本）。卡片滑入 = 新卡片从右下 `translate(120%, 20%)` 进来同时上一张退到左上并缩小 6%。
- **优点**：和纸艺画风天然契合；信息密度高，适合快歌。
- **代价**：不适合慢歌（会显得急）；每张卡片自己要有信息，不然就是乱晃。

## 选哪个：判断表

| 条件 | 推荐 |
|---|---|
| 画风 = 纸艺拼贴 + 歌 ≤ 130 BPM | **方案 3 拼贴快切**（纸的性格就是「翻页」） |
| 画风 = 纸艺 + 歌 ≥ 130 BPM，副歌强 | **方案 2 卡点切换**（副歌甩镜，主歌硬切） |
| 画风 = 像素 | **方案 2 卡点切换**（像素的「跳帧」和硬切是一路的） |
| 画风 = 蜡笔 | **方案 1 一镜到底**（蜡笔的连续线条不该被打断）；或方案 2 + 只用「前景扫过」 |
| 歌词叙事性强、场景多 | **方案 1** 或「方案 2 + match cut（动作接动作）」 |
| 用户要「电影感」 | **方案 1** |
| 用户要「抖音感/卡点」 | **方案 2** |

**混合是允许的**：主歌硬切 + 副歌甩镜 + 桥段一镜到底，是最常见的成熟做法。**但要在 storyboard.md 里写清楚哪段用哪种**，不能随机。

## 每条转场必须满足（三条硬检查）

1. **每次转场都有衔接**：起点对齐节拍；承接角色动作或画面元素（上一镜结束的手势 = 下一镜开始的手势）。
2. **衔接帧前后角色的大小、位置、姿态一致**，不发生瞬移。做法：把上一镜最后一帧和下一镜第一帧的 `MVChar.pose()` 参数写成同一组值，只改背景。
3. **镜头推拉时画面元素不突然消失或出现**。做法：所有元素在 `t=0` 就已存在于 DOM，只改 `opacity` / `transform`，绝不用 `display: none` 或 GSAP 的 `autoAlpha`（HyperFrames 明确禁止在 `.clip` 上 tween `display/visibility/autoAlpha`）。

## 禁止

- **无衔接的硬切**（除了明确的「段落断裂」，全片最多允许 2 次）
- **整屏叠化**（crossfade 叠满屏是最廉价的做法；要叠只叠局部元素）
- **镜头频繁来回推拉或晃动**（推一下又拉回来，观众会晕）

## 写回 storyboard.md

在每个 Frame 的 `transition_in` 里填具体方式，并在文件末尾加一张总表：

```markdown
## 转场总表

方案：主体 方案 2 卡点切换；桥段（1:52-2:20）用方案 1 一镜到底。

| 从 → 到 | 时间 | 方式 | 承接物 | 对齐节拍 |
|---|---|---|---|---|
| 01 → 02 | 4.20 | cut（硬切） | 猫落地 → 角色脚落地 | 4.51 |
| 02 → 03 | 8.60 | whip（右甩） | 角色视线方向 | 8.51 |
| 03 → 04 | 12.10 | match（动作接） | 抬手 → 抬手 | 12.05 |
| 04 → 05 | 15.80 | card（卡片滑入） | — | 16.01 |

### 衔接帧一致性
| 边界 | 角色位置 | 角色大小 | 姿态参数 |
|---|---|---|---|
| 02/03 | (960, 820) → (960, 820) | 1.0 → 1.0 | walk, u=0.75 → walk, u=0.0 |
| 03/04 | (720, 860) → (720, 860) | 1.05 → 1.05 | hold → hold |
```

这张表是 06 出关键帧和 07 实现时的唯一依据。**表里对不上的地方就是会瞬移的地方。**
